# Satellite Data Lab — 仕様書

最終更新: 2026-09-21（JA/EN 対応・全画面トグル反映）

## 1. 概要

| 項目 | 内容 |
| --- | --- |
| 名称 | Satellite Data Lab（リポジトリ名 `geobyte-interactive`） |
| 目的 | 衛星データ利用を学ぶ**エンジニア・実務者向け**のインタラクティブ教材。数式や用語の暗記ではなく、パラメータを動かし実データを触って「なぜそうなるか」を体感させる |
| 形式 | Web アプリ（SPA + SSR）。6 モジュール構成、各モジュールは独立して閲覧可能 |
| 本番 URL | https://geobyte-interactive.vercel.app |
| リポジトリ | https://github.com/finetomorrow2001/geobyte-interactive （public） |
| デプロイ | GitHub `main` への push → Vercel 自動デプロイ |
| 言語 | 日本語 / 英語の切替（§3.1）。日本語モードでは専門用語に英語を併記 |

### 設計原則

1. **サーバーレス・鍵不要** — 自前バックエンドも API キーも持たない。外部の公開データ（STAC・COG・TLE・地図タイル）にブラウザから直接アクセスする。
2. **実データ優先** — 合成データで原理を示したあと、必ず Sentinel-2 の実データで同じことを確認できるようにする。
3. **遅延読み込み** — ユーザーが選ぶまで重いリソース（衛星写真ベースマップ、標高タイル、COG）を取得しない。
4. **計算はクライアントで** — 再投影・バンド合成・指標計算・SGP4 伝播をすべてブラウザ（主に Web Worker）で行い、Network タブでその様子を観察できる状態にする。

### 3.1 多言語（JA / EN）

- 実装: `src/lib/i18n/lang.svelte.ts`。`i18n.lang` は runes の `$state`。初期値は `localStorage('sdl-lang')` → `navigator.language` → `ja`。切替で `<html lang>` も更新。
- 辞書はページ単位 `src/lib/i18n/<page>.ts`（`{ ja: {...}, en: {...} } satisfies Bilingual`）。コンポーネントでは `const t = makeT(dict)` → `{t('key')}`、可変部分は関数エントリ `{t('count', n)}`。インライン `<strong>`/`<code>` を含む文は `{@html t('key')}`。

- 方針「切替 + 用語併記」: 日本語側は各パネル初出の専門用語に英語を括弧で添える（例:「観測幅 (swath)」）。英語側は併記なし。`term(ja, en)` ヘルパーも用意。

## 4. モジュール仕様

### 01 軌道と再訪周期 `/orbits`

- 入力: 高度 [km]、観測幅 [km]。プリセット（ISS, PlanetScope, Sentinel-1/2, Landsat, MODIS, ひまわり）。
- 出力: 周期、1 日の周回数、軌道速度・地上速度、赤道での軌跡間隔、単機再訪日数、太陽同期傾斜角（J2 摂動）、地平線距離。
- 学び: なぜ地球観測衛星が高度 500–800 km に集まるか、観測幅と再訪のトレードオフ。

### 02 スペクトルと指標 `/spectral`

- Sentinel-2 の 13 バンド定義と地物（植生・水・土壌・雪・都市・雲）の反射スペクトル。
- 任意の 2 バンドで正規化差分指標 `(a−b)/(a+b)` を組み立て、合成シーン（`makeScene`）に適用。
- バンド合成（トゥルー/フォールスカラー等）を合成シーンで比較。

### 03 分解能のトレードオフ `/resolution`

- 空間・時間・スペクトル・放射の 4 軸。GSD とビット深度のスライダーで画像劣化を確認。
- ミッション比較の散布図（`missions.ts`: GSD × 観測幅 × 再訪、光学/SAR/静止、無償/有償）。

### 04 STAC でデータ取得 `/stac`

- Earth Search（AWS, `sentinel-2-l2a`）へ実際に POST 検索。bbox・期間・雲量上限をフォームで組み立て。
- 生成されるリクエスト JSON と `pystac-client` 相当のコードを表示。結果はサムネイル一覧、Item を 06 に渡すリンク（`/imagery?item=<id>`）。

### 05 データ形式と処理レベル `/formats`

- COG のタイル/オーバービュー構造と HTTP Range Request、Zarr のチャンク、処理レベル L0–L2 / ARD、SAR の特徴を図解。

### 06 実画像を見る `/imagery` — 詳細は §5

### 5.2 データソース

| 用途 | ソース | 読込タイミング |
| --- | --- | --- |
| シーン検索 | Earth Search STAC v1 `POST /search`（地図中心 ±0.02° の bbox、期間、雲量） | 初期表示・場所移動・再検索ボタン |
| 画像 | `sentinel-cogs` S3 の COG（`visual`, `red`, `green`, `blue`, `nir`, `nir08`, `swir16`, `swir22`） | シーン A/B 選択・モード変更時、表示中タイルのみ |
| ベースマップ（地図） | OpenStreetMap ラスタタイル | 常時 |
| ベースマップ（衛星写真） | Esri World Imagery | **「衛星写真」を初めて選んだ時**。標準地図モードでは一切取得しない |
| 標高 | AWS Terrain Tiles（terrarium） | **3D を初めて選んだ時** |
| TLE | CelesTrak `gp.php?NAME=SENTINEL-2&FORMAT=tle` | ページ表示時。localStorage に 6 時間キャッシュ、失敗時は同梱スナップショット（2026-09-20 取得） |

### 5.3 レンダリングパイプライン（COG → 地図タイル）

1. MapLibre が `cog://<key>/{z}/{x}/{y}` をリクエスト（カスタムプロトコル、`cog-protocol.ts`）。
2. メインスレッドは Worker プール（2–4 本、隣接 2×2 タイルは同じ Worker）へジョブ送信。
3. Worker（`cog.worker.ts`）: geotiff.js で COG ヘッダを読み、表示ズームに合うオーバービューを選択 → タイルの UTM 範囲を 17×17 格子 + 双線形補間で求め（誤差 < 0.8 m）→ 必要な内部タイルだけ Range Request → 最近傍サンプリング → 合成 / 指標 + カラーマップ → RGBA。
4. メインスレッドで `createImageBitmap` → MapLibre に返す（PNG エンコード不要）。
5. ソース設定: `tileSize 256, minzoom 8, maxzoom 15, bounds = item.bbox`。z16 以上は MapLibre 側で拡大（COG を読み直さない）。指標は `raster-resampling: nearest`。

表示モード: 合成 6 種（TCI, 自前 RGB, フォールスカラー, SWIR, 農業, 都市）+ 指標 6 種（NDVI, NDWI, NDMI, NBR, NDSI, NDBI）。ゲイン（rescale 上限）、不透明度。

### 5.4 比較（A/B スワイプ）

- B を選ぶと**2 枚目の MapLibre** を生成し、カメラ（center/zoom/bearing/pitch）を相互同期。B のコンテナを `clip-path: inset(0 0 0 swipe%)` で右側のみ表示。B 解除で破棄。
- 境界は橙の縦線 + 中央の「A ◀ ▶ B」つまみ（ポインタキャプチャでドラッグ、矢印キーで ±1%）。地図全幅の `<input type=range>` は右上の時刻バーと重なるため廃止。
- ベースマップ・3D・フットプリント・クリック地点・軌道レイヤーは両方の地図に適用。

### 5.5 3D / 全画面 / コンパス

- 全画面 ⛶: 地図コンテナを Fullscreen API で全画面化。全画面中は同じボタンが「全画面を終了 (Esc)」の文字付きに変わる。API が使えない／拒否された場合は `.fullscreen` クラスで `position: fixed; inset: 0` にフォールバック。切替後に両地図へ `resize()`。
- 3D: `raster-dem`（terrarium）を地形に設定（exaggeration 1.3）+ hillshade レイヤー、pitch 60° へアニメーション。2D で地形解除・pitch 0。maxPitch 70。
- 操作: 右ドラッグ / Ctrl+ドラッグで回転・傾き。
- コンパス（`Compass.svelte`）: 地図の bearing に追従、クリックで北上。傾き角を中央に表示。
  - **● 太陽**: シーン A の `view:sun_azimuth`（STAC）。雲の影はこの反対方向。
  - **▲ 衛星の進行方向**: 直近の撮影パスの方位（下降軌道、日本付近で約 194°）。

### 5.6 衛星軌道レイヤー（`s2orbit.ts`）

- 対象: Sentinel-2A (40697) / 2B (42063) / 2C (60989)。色: シアン / 緑 / 橙。
- 伝播: satellite.js SGP4。直下点 = `eciToGeodetic(propagate(), gstime())`。
- 描画（1 秒ごとに更新、計算 ≈ 2 ms）:
  - 現在位置マーカー（DOM Marker、ラベル S2A/S2B/S2C）
  - 表示時刻 ±50 分の軌道直下の軌跡。**撮影中**（下降中 ∧ 直下点の太陽高度 > 5°）は実線、それ以外は点線
  - 撮影区間の**観測幅ポリゴン**（直下点の両側 145 km、幅 290 km）
  - **いま見ている 1 ライン**（進行方向に直交する 290 km の太線）
  - 選択パスの軌跡（太線）と観測幅（±5 分）
- 経度は `unwrapLons` で連続値にし、±180° の扱いは MapLibre の世界コピー描画に任せる。
- 時刻バー: 表示時刻 = 現在 + オフセット [分]。`−1d/−1h/▶(60 倍速)/+1h/+1d/LIVE`。スライダーの範囲は過去側 = シーン検索期間（既定 90 日）、未来側 = +10 日。スライダー下に目盛り: 検索結果のシーン撮影時刻（衛星色、過去）・予測パス（薄色、未来）・現在（緑線）。目盛りクリックでその時刻へ。パス行クリックも同様。
- **画像の時刻同期**（既定 ON）: LIVE 以外では、表示時刻の直前（+1 分許容）に撮影されたシーンへ画像 A を自動で切り替える。スクラブ中にサムネイルを手で選ぶと、逆に表示時刻がそのシーンの撮影時刻へ飛ぶ（衛星が真上に来る）。衛星位置は連続だが画像は撮影日ごとの静止画である、という違いを UI で示す。
- 最寄り衛星の読み出し: 表示時刻に地図中心へ最も近い衛星と直下点までの距離。
- 「🛰 軌道 ON/OFF」でレイヤー・マーカー・時刻バーをまとめて表示切替。

### 5.7 パス予測（「次にここが撮影されるのは」）

- 3 機の直下点列を 10 日分・60 秒刻みで計算しキャッシュ（目標地点に依存しない）。
- 各区間を大圏とみなし、目標の横方向距離 `xt` と沿線距離 `at` を球面三角法で求め、`0 ≤ at ≤ 区間長` かつ `|xt| < 400 km` を候補に。最接近時刻は線形補間。
- 表示条件: 下降（昼側）かつ `|xt| < 145 km`。列: JST 日時、衛星、横ずれ [km]、太陽高度、**10 日前 ✓**（同じ衛星が 10 日周期 ±3 分前にこの場所を撮ったシーンが検索結果にあれば、その日付と相対軌道番号）。
- 地図 `moveend` の 600 ms 後に地図中心で再計算。
- 検証実績: 2A の予測パス 2026-09-20T01:37:35.46Z vs STAC 実撮影 01:37:35.618Z（差 0.2 秒）。太陽方位・高度も STAC 値と 0.1° 以内。

### 5.8 地点クエリ・時系列・メタデータ

- 地図クリック → 7 バンド DN（`blue, green, red, nir, nir08, swir16, swir22`）と 6 指標を A（と B、差分）で表示。COG からフル解像度で該当 1 画素を含む内部タイルだけ読む。
- 時系列: 検索結果の最新 20 シーンから同一画素の指標値を並列取得しプロット。雲量 > 20% のシーンは橙。
- シーン A メタデータ: 衛星 / 相対軌道（`s2:product_uri` の `_R###_`）、JST 時刻、MGRS タイル、太陽方位/高度、視線方位/入射角、軌道方向。

### 5.9 URL パラメータ

- `/imagery?item=<STAC item id>` — 04 からの導線。指定 Item を直接 A に表示（検索は行わない）。

## 6. 非機能要件

- **性能**: NDVI 切替 12 タイル ≈ 6.6 s（初回、COG 直読み）、メインスレッド最大遅延 ≈ 2 ms。Worker 内タイルキャッシュ 120 枚（≈ 60 MB）。軌道更新 ≈ 2 ms / 秒。
- **外部依存の障害時**: STAC 失敗 → 警告表示。CelesTrak 失敗 → 同梱 TLE（出所を表示）。タイル失敗 → その部分が空白。
- **プライバシー**: 外部送信するのは STAC 検索 bbox のみ。Cookie・トラッキングなし。localStorage は TLE キャッシュのみ。
- **対応環境**: WebGL2 と Module Worker が使えるモダンブラウザ。非表示タブでは MapLibre が rAF 待ちで初期化を保留する（仕様）。

## 7. 既知の制約・ハマりどころ

| 事項 | 内容 |
| --- | --- |
| satellite.js | 7.x の WASM/pthreads ビルドが `node:worker_threads` を含み Vite build が失敗 → **6.x に固定** |
| maplibre-gl v6 | Worker が別ファイル。`import url from 'maplibre-gl/dist/maplibre-gl-worker.mjs?worker&url'` + `setWorkerUrl(url)`、`optimizeDeps.exclude` が必要。SSR 不可のため動的 import |
| MapLibre のテキスト | `symbol` レイヤーに glyphs が必要なため使わず、ラベルは DOM Marker |
| 比較モード | 2 枚目の地図でベースマップのタイル取得が倍になる |
| TLE の精度 | 数日先までは秒単位で一致。数週間以上の予測や過去への逆伝播は誤差が大きい（過去の撮影位置の再現には使わない） |
| 撮影予測 | 「陸域は系統的に撮影」の前提。実際にシーンが公開されるかは取得計画・処理状況に依存 |
| Vercel | `vercel --prod` はローカル権限で拒否されるため、デプロイは push 経由 |
