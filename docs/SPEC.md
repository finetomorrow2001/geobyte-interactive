# Satellite Data Lab — 仕様書

最終更新: 2026-09-21（commit `e151c7c` 時点）。開発手順・検証方法は [DEVELOPMENT.md](DEVELOPMENT.md)、変更履歴は §9。

## 1. 概要

| 項目 | 内容 |
| --- | --- |
| 名称 | Satellite Data Lab（リポジトリ名 `geobyte-interactive`） |
| 目的 | 衛星データ利用を学ぶ**エンジニア・実務者向け**のインタラクティブ教材。数式や用語の暗記ではなく、パラメータを動かし実データを触って「なぜそうなるか」を体感させる |
| 形式 | Web アプリ（SPA + SSR）。6 モジュール構成、各モジュールは独立して閲覧可能 |
| 本番 URL | https://geobyte-interactive.vercel.app |
| リポジトリ | https://github.com/finetomorrow2001/geobyte-interactive （public） |
| デプロイ | GitHub `main` への push → Vercel 自動デプロイ |
| 言語 | 日本語 / 英語の切替（§3.1）。日本語モードでは専門用語に英語を併記 |

### 設計原則

1. **サーバーレス・鍵不要** — 自前バックエンドも API キーも持たない。外部の公開データ（STAC・COG・TLE・地図タイル）にブラウザから直接アクセスする。
2. **実データ優先** — 合成データで原理を示したあと、必ず Sentinel-2 の実データで同じことを確認できるようにする。
3. **遅延読み込み** — ユーザーが選ぶまで重いリソース（衛星写真ベースマップ、標高タイル、COG）を取得しない。
4. **計算はクライアントで** — 再投影・バンド合成・指標計算・SGP4 伝播をすべてブラウザ（主に Web Worker）で行い、Network タブでその様子を観察できる状態にする。

### 3.1 多言語（JA / EN）

## 4. モジュール仕様

### 01 軌道と再訪周期 `/orbits`

- 入力: 高度 [km]、観測幅 [km]。プリセット（ISS, PlanetScope, Sentinel-1/2, Landsat, MODIS, ひまわり）。
- 出力: 周期、1 日の周回数、軌道速度・地上速度、赤道での軌跡間隔、単機再訪日数、太陽同期傾斜角（J2 摂動）、地平線距離。
- 学び: なぜ地球観測衛星が高度 500–800 km に集まるか、観測幅と再訪のトレードオフ。

### 02 スペクトルと指標 `/spectral`

- Sentinel-2 の 13 バンド定義と地物（植生・水・土壌・雪・都市・雲）の反射スペクトル。
- 任意の 2 バンドで正規化差分指標 `(a−b)/(a+b)` を組み立て、合成シーン（`makeScene`）に適用。
- バンド合成（トゥルー/フォールスカラー等）を合成シーンで比較。

### 03 分解能のトレードオフ `/resolution`

- 空間・時間・スペクトル・放射の 4 軸。GSD とビット深度のスライダーで画像劣化を確認。
- ミッション比較の散布図（`missions.ts`: GSD × 観測幅 × 再訪、光学/SAR/静止、無償/有償）。

### 04 STAC でデータ取得 `/stac`

- Earth Search（AWS, `sentinel-2-l2a`）へ実際に POST 検索。bbox・期間・雲量上限をフォームで組み立て。
- 生成されるリクエスト JSON と `pystac-client` 相当のコードを表示。結果はサムネイル一覧、Item を 06 に渡すリンク（`/imagery?item=<id>`）。

### 05 データ形式と処理レベル `/formats`

- COG のタイル/オーバービュー構造と HTTP Range Request、Zarr のチャンク、処理レベル L0–L2 / ARD、SAR の特徴を図解。

### 06 実画像を見る `/imagery` — 詳細は §5

### 5.3 レンダリングパイプライン（COG → 地図タイル）

1. MapLibre が `cog://<key>/{z}/{x}/{y}` をリクエスト（カスタムプロトコル、`cog-protocol.ts`）。
2. メインスレッドは Worker プール（2–4 本、隣接 2×2 タイルは同じ Worker）へジョブ送信。
3. Worker（`cog.worker.ts`）: geotiff.js で COG ヘッダを読み、表示ズームに合うオーバービューを選択 → タイルの UTM 範囲を 17×17 格子 + 双線形補間で求め（誤差 < 0.8 m）→ 必要な内部タイルだけ Range Request → 最近傍サンプリング → 合成 / 指標 + カラーマップ → RGBA。
4. メインスレッドで `createImageBitmap` → MapLibre に返す（PNG エンコード不要）。
5. ソース設定: `tileSize 256, minzoom 8, maxzoom 15, bounds = item.bbox`。z16 以上は MapLibre 側で拡大（COG を読み直さない）。指標は `raster-resampling: nearest`。

表示モード: 合成 6 種（TCI, 自前 RGB, フォールスカラー, SWIR, 農業, 都市）+ 指標 6 種（NDVI, NDWI, NDMI, NBR, NDSI, NDBI）。ゲイン（rescale 上限）、不透明度。

### 5.4 比較（A/B スワイプ）

- B を選ぶと**2 枚目の MapLibre** を生成し、カメラ（center/zoom/bearing/pitch）を相互同期。B のコンテナを `clip-path: inset(0 0 0 swipe%)` で右側のみ表示。B 解除で破棄。
- 境界は橙の縦線 + 中央の「A ◀ ▶ B」つまみ（ポインタキャプチャでドラッグ、矢印キーで ±1%）。地図全幅の `<input type=range>` は右上の時刻バーと重なるため廃止。
- ベースマップ・3D・フットプリント・クリック地点・軌道レイヤーは両方の地図に適用。

### 5.5 3D / 全画面 / コンパス

- 全画面 ⛶: 地図コンテナを Fullscreen API で全画面化。全画面中は同じボタンが「全画面を終了 (Esc)」の文字付きに変わる。API が使えない／拒否された場合は `.fullscreen` クラスで `position: fixed; inset: 0` にフォールバック。切替後に両地図へ `resize()`。
- 3D: `raster-dem`（terrarium）を地形に設定（exaggeration 1.3）+ hillshade レイヤー、pitch 60° へアニメーション。2D で地形解除・pitch 0。maxPitch 70。
- 操作: 右ドラッグ / Ctrl+ドラッグで回転・傾き。
- コンパス（`Compass.svelte`）: 地図の bearing に追従、クリックで北上。傾き角を中央に表示。
  - **● 太陽**: シーン A の `view:sun_azimuth`（STAC）。雲の影はこの反対方向。
  - **▲ 衛星の進行方向**: 直近の撮影パスの方位（下降軌道、日本付近で約 194°）。

### 5.6 衛星軌道レイヤー（`s2orbit.ts`）

- 対象: Sentinel-2A (40697) / 2B (42063) / 2C (60989)。色: シアン / 緑 / 橙。
- 伝播: satellite.js SGP4。直下点 = `eciToGeodetic(propagate(), gstime())`。
- 描画（1 秒ごとに更新、計算 ≈ 2 ms）:
  - 現在位置マーカー（DOM Marker、ラベル S2A/S2B/S2C）
  - 表示時刻 ±50 分の軌道直下の軌跡。**撮影中**（下降中 ∧ 直下点の太陽高度 > 5°）は実線、それ以外は点線
  - 撮影区間の**観測幅ポリゴン**（直下点の両側 145 km、幅 290 km）
  - **いま見ている 1 ライン**（進行方向に直交する 290 km の太線）
  - 選択パスの軌跡（太線）と観測幅（±5 分）
- 経度は `unwrapLons` で連続値にし、±180° の扱いは MapLibre の世界コピー描画に任せる。
- 時刻バー: 表示時刻 = 現在 + オフセット [分]。`−1d/−1h/▶(60 倍速)/+1h/+1d/LIVE`。スライダーの範囲は過去側 = シーン検索期間（既定 90 日）、未来側 = +10 日。スライダー下に目盛り: 検索結果のシーン撮影時刻（衛星色、過去）・予測パス（薄色、未来）・現在（緑線）。目盛りクリックでその時刻へ。パス行クリックも同様。
- **画像の時刻同期**（既定 ON）: LIVE 以外では、表示時刻の直前（+1 分許容）に撮影されたシーンへ画像 A を自動で切り替える。スクラブ中にサムネイルを手で選ぶと、逆に表示時刻がそのシーンの撮影時刻へ飛ぶ（衛星が真上に来る）。衛星位置は連続だが画像は撮影日ごとの静止画である、という違いを UI で示す。
- 最寄り衛星の読み出し: 表示時刻に地図中心へ最も近い衛星と直下点までの距離。
- 画像の古さの読み出し（LIVE 以外）: 「表示中の画像: MM-DD 撮影（表示時刻の Nd Nh 前の静止画）」と「次の撮影 MM-DD SxX まで画像は変わりません」（検索結果に無ければその旨）。同期で画像が切り替わった瞬間は地図中央にトースト（2.5 s）+ 凡例を点滅。
- 設計意図: 衛星の位置は連続だが、画像は数日おきの撮影ごとの静止画であり、時間単位のスクラブでは変わらない——この非対称を UI で読み取れるようにする。
- 「🛰 軌道 ON/OFF」でレイヤー・マーカー・時刻バーをまとめて表示切替。

### 5.7 パス予測（「次にここが撮影されるのは」）

- 3 機の直下点列を 10 日分・60 秒刻みで計算しキャッシュ（目標地点に依存しない）。
- 各区間を大圏とみなし、目標の横方向距離 `xt` と沿線距離 `at` を球面三角法で求め、`0 ≤ at ≤ 区間長` かつ `|xt| < 400 km` を候補に。最接近時刻は線形補間。
- 表示条件: 下降（昼側）かつ `|xt| < 145 km`。列: JST 日時、衛星、横ずれ [km]、太陽高度、**10 日前 ✓**（同じ衛星が 10 日周期 ±3 分前にこの場所を撮ったシーンが検索結果にあれば、その日付と相対軌道番号）。
- 地図 `moveend` の 600 ms 後に地図中心で再計算。
- 検証実績: 2A の予測パス 2026-09-20T01:37:35.46Z vs STAC 実撮影 01:37:35.618Z（差 0.2 秒）。太陽方位・高度も STAC 値と 0.1° 以内。

### 5.8 地点クエリ・時系列・メタデータ

- 地図クリック → 7 バンド DN（`blue, green, red, nir, nir08, swir16, swir22`）と 6 指標を A（と B、差分）で表示。COG からフル解像度で該当 1 画素を含む内部タイルだけ読む。
- 時系列: 対象シーンから同一画素の指標値を並列取得しプロット（最新 20 シーンまで）。雲量 > 20% のシーンは橙。対象は切替で選ぶ。
  - **再計算の規則**: 計算済みの場合に限り、地点クリック・対象/指標の切替・年次の再検索・候補差し替えで自動的に再計算する。A/B の年選択だけでは消さない（A/B の値だけを `refreshPoint` で取り直す）。計算済みでなければ何もしない。
  - **SCL マスク（共通）**: 点・時系列・指数画像は `src/lib/scl.ts` の同じ判定を使う。SCL（20 m）が 欠測(0)・飽和(1)・雲影(3)・雲(8,9)・巻雲(10)・雪(11) の画素は**欠測**として扱い、0 に置き換えない。暗域(2)・未分類(7)・植生(4)・裸地(5)・水(6) は有効。点の表は SCL の値とクラス名を表示し、欠測の理由を明記する（バンド DN は観測値のまま）。時系列では欠測の年を灰色の ○ で示し、ツールチップに理由を出す。SCL アセットがないシーンはマスクできない（表示は `—`）。
  - **最近傍**: SCL は分類値なので補間しない。点は 20 m 画素の包含判定、タイルは出力画素 → 経緯度 → UTM → SCL 画素の最近傍。SCL.tif のオーバービューも最近傍で作られている（8 倍までの各階層で、各画素が元の 2×2 のいずれかと一致することを確認）ので、低ズームでも分類値は壊れない。
  - **指数画像**: 指数モードだけ SCL で透過（欠測）にする。真色・合成はマスクしない（雲を見せるため）。凡例に「指数画像: 雲・雲影・巻雲・雪・欠測は透過（SCL）」を表示。
  - **反射率**: `src/lib/reflectance.ts`。`earthsearch:boa_offset_applied === true` なら DN は補正済みで追加のオフセットを引かない。`false` でベースライン < 04.00 ならオフセットなし。`false`/未設定でベースライン ≥ 04.00 のときだけ 1000 を引く（現在の Earth Search では該当なし）。指数は反射率で計算（Worker のタイルも `dnOffset` を受け取る）。`raster:bands.offset = −0.1` は使わない（使うと二重補正）。
  - **検索結果（最新）**: 縦軸は −1〜1 固定、横軸ラベルは `MM-DD`。
  - **年次比較のシーン**（§5.10）: 横軸ラベルは `YYYY-MM`。年ごとの差は小さいので、縦軸を値の最小〜最大に ±20%（最低 ±0.02）の余白を付けて拡大する（−1〜1 でクリップ）。
- シーン A メタデータ: 衛星 / 相対軌道（`s2:product_uri` の `_R###_`）、JST 時刻、MGRS タイル、太陽方位/高度、視線方位/入射角、軌道方向。

### 5.10 夕張の南北比較と年次比較（`annual.ts` / `studyAreas`）

- **地域選択**: 「夕張・南側（紅葉山・沼ノ沢周辺）」「夕張・北側（南清水沢・鹿の谷周辺）」。範囲は公開地名から置いた**概略の表示範囲**（`studyAreas.bbox`）で、林班境界・入林可能範囲・通行可否ではない（画面にも明記）。選択すると検索・A/B・地点・時系列を一旦リセットし、範囲へ `fitBounds`。年次検索は地図を動かしても選択地域の bbox を使う（未選択なら検索時の地図中心 ±0.02°）。
- **個人情報の扱い**: 個人の地図画像・入林予定・林班番号・申請情報はアプリ・Git・`static`・デプロイ成果物に含めない。詳細範囲が必要ならローカル専用の設定にする。
- **比較条件（すべて仮の初期値で UI から変更可）**: 基準月日（既定 10-02、UTC）、シーン全体の雲量上限（30%）、前後日数（0/7/14/30、既定 14）、年数（2〜9、既定 8）、「同日の撮影がない年も近い日付で代替する」（既定 OFF＝欠測）。
- **選定ロジック**（`chooseAnnual`、テストあり）: 2017 年以降で基準日が現在より過去の年を新しい方から `years` 個。シーンの輪郭が表示 bbox の四隅と中心を全て覆うものだけを候補にする（`coversBox`）。
  1. 同日に雲量上限以下のシーンがあれば採用（理由 `exact`）。
  2. 同日の撮影はあるが全て雲量超過 → 前後日数内の最も近い日（同距離なら低雲量）で代替（`cloud-adjusted`、代替なしは `cloud-no-alternative`）。
  3. 同日の撮影がない → 既定は欠測（`no-acquisition`）。代替を許可した場合のみ近傍日で代替（`no-acquisition-adjusted`）。
  4. 雲量が欠落・範囲外（<0, >100, NaN）なら採用せず `quality-unknown`。存在しない日付（非うるう年の 02-29）は `invalid-date`。
- **表示**: 年カードに実際の撮影日、基準日、基準日との差（±N 日）、理由、候補数。候補が複数ある年は候補リストで撮影日を手動差し替えでき、その場合の理由は `manual-quality-adjusted`（同日の画像に戻せば `exact` に戻る。`manualSelect`）。サムネイルは**シーン全体**で、地域の切出しではない。
- **地域内の SCL 集計（年カード）**: 採用中の各シーンについて、選択範囲を **150×150 の格子（セル中心）**で SCL（20 m）に最近傍で対応付けて数える（`regionStats` → Worker の `stats` ジョブ → `sampleGrid` + `summarizeScl`）。**分母は全格子点（22,500。画像範囲外=255 と SCL=0 を含む）**。表示は 有効% ｜ 雲(8+9)・影(3)・巻雲(10)・雪(11)・欠測+範囲外(0,1,255)（%）。有効 = 無効クラス（0,1,3,8,9,10,11）以外。カードの ☁ はシーン全体の雲量で別の値。定義文は画面（年次比較パネル）とカードのツールチップ、JSON 保存にも載る。同時実行数は 4 に制限し、検索が変わった結果は捨てる。
- **地域内の無効画素率による再選定（任意・既定は手動ボタン）**: 「地域内の晴れ具合で再選定」（上限は UI、既定 20% は仮設定）。採用中のシーンの無効率が上限を超える年だけ候補（その年の `alternatives`）を集計し、基準日に最も近い上限以下の候補へ差し替える（`reselectByRegion`、テストあり）。差し替えた年は理由 `region-adjusted`・基準日との差・変更前の撮影日と無効率をカードとJSONに残す。条件を満たす候補がなければ変更せず、その旨を表示。A/B が差し替え前のシーンだった場合は新しいシーンへ追従する。
- **再現手順**: `node --experimental-strip-types scripts/scl-region-stats.mjs both [YYYY-MM-DD ...]`（アプリと同じ `sampleGrid`/`summarizeScl` を使う）。結果は `docs/analysis/yubari-scl-region-stats.json`、説明は `docs/analysis/README.md`。
- **品質の注意**: 雲量は**シーン全体**の値で、対象地域の晴れ具合を保証しない。自然色で雲・影・雪を目視確認する前提。
- **JSON 保存**: 「取得日・代替理由・データURLをJSON保存」で、検索条件・地域 bbox・各年の行（候補を含む）・注意書きを保存（ブラウザのダウンロード。サーバー送信なし）。
- **状態の分離**: 検索・地点値・時系列・B 地図の非同期処理にはバージョン番号を付け、地域切替や再検索後に古い結果が混入しない。軌道表示・時刻同期・再生の設定は検索や地域選択で変更しない。
- **タイル状態**: B 側にも「B 読込中…」を境界線の右に表示。A/B とも `cog-a`/`cog-b` のタイル取得失敗数と最後のエラーメッセージ（先頭 120 字）を地図左上に表示。**画像範囲外**: 表示範囲の 7×7 格子のうち A/B のシーン輪郭に入る割合を `moveend`・レイヤー更新ごとに求め、98% 未満なら凡例に「撮影範囲外を含む（n% のみ撮影）」、2% 未満なら「表示範囲は撮影範囲外」と表示。**欠測**: 指数モードの透過は凡例の注記で示す。

## 6. 非機能要件

- **性能**: NDVI 切替 12 タイル ≈ 6.6 s（初回、COG 直読み）、メインスレッド最大遅延 ≈ 2 ms。Worker 内タイルキャッシュ 120 枚（≈ 60 MB）。軌道更新 ≈ 2 ms / 秒。パス予測の初回（10 日 × 3 機の直下点列生成）は ≈ 85–230 ms のメインスレッド長タスクが 1 回発生（以後キャッシュ、§8.2 に改善案）。
- **アクセシビリティ**: 境界のつまみは `role="slider"` + 矢印キー、コンパス・全画面・目盛りは `aria-label` 付き。
- **外部依存の障害時**: STAC 失敗 → 警告表示。CelesTrak 失敗 → 同梱 TLE（出所を表示）。タイル失敗 → その部分が空白。
- **プライバシー**: 外部送信するのは STAC 検索 bbox のみ。Cookie・トラッキングなし。localStorage は TLE キャッシュのみ。
- **対応環境**: WebGL2 と Module Worker が使えるモダンブラウザ。非表示タブでは MapLibre が rAF 待ちで初期化を保留する（仕様）。

## 7. 既知の制約・ハマりどころ

| 事項 | 内容 |
| --- | --- |
| 反射率の扱い | Earth Search は処理ベースライン ≥ 04.00 のシーンに BOA オフセットを適用済み（`earthsearch:boa_offset_applied: true`）で、DN ÷ 10000 = 反射率。コードは追加のオフセットを引かない（二重補正なし）。`raster:bands` の `offset: -0.1` はメタデータ上の記載で、`boa_offset_applied` が true なら適用済みとして扱う。2022-10 以降の NIR 最小 DN が 45〜243 で、1000 の床がないことを実測で確認 |
| SCL の限界 | SCL はモデルによる分類で真値ではない。同じ日付でも処理バージョン（`_0_` と `_1_`）で結果が違う（夕張南側 2021-10-09: 25.5% と 42.4%）。暗域(2)・未分類(7)は除外しないので、薄い雲や雲影の取りこぼしがありうる。10 m の画素に 20 m の SCL を最近傍で当てるため、雲の縁は ±1 画素ずれうる。マスク後の時系列も「参考」であり、植生の経年変化の確定には使わない |
| 年次比較の品質 | 初回の選定はシーン全体の雲量と輪郭の被覆（bbox の 5 点）で行う。地域内の晴れ具合は年カードの SCL 集計（§5.10）と「地域内の晴れ具合で再選定」で確認する。再選定の候補は、シーン全体の雲量が上限以下のものに限る（上限超のシーンは地域内が晴れていても候補に入らない） |
| satellite.js | 7.x の WASM/pthreads ビルドが `node:worker_threads` を含み Vite build が失敗 → **6.x に固定** |
| maplibre-gl v6 | Worker が別ファイル。`import url from 'maplibre-gl/dist/maplibre-gl-worker.mjs?worker&url'` + `setWorkerUrl(url)`、`optimizeDeps.exclude` が必要。SSR 不可のため動的 import |
| MapLibre のテキスト | `symbol` レイヤーに glyphs が必要なため使わず、ラベルは DOM Marker |
| 比較モード | 2 枚目の地図でベースマップのタイル取得が倍になる |
| TLE の精度 | 数日先までは秒単位で一致。数週間以上の予測や過去への逆伝播は誤差が大きい（過去の撮影位置の再現には使わない） |
| 撮影予測 | 「陸域は系統的に撮影」の前提。実際にシーンが公開されるかは取得計画・処理状況に依存 |
| Vercel | `vercel --prod` はローカル権限で拒否されるため、デプロイは push 経由 |
| 画像とスライダー | 画像は撮影日ごとの静止画。時刻スライダーを時間単位で動かしても画像は変わらず、撮影時刻（目盛り）を跨いだ時だけ切り替わる。雲量上限を上げるか、2 つの相対軌道が重なる場所（十勝など）を選ぶと間隔が詰まる |
| 非表示タブ | `document.hidden` の間は rAF が止まり MapLibre がスタイル読込を保留する（初期化が「止まって見える」）。表示に戻れば再開 |

### 8.2 06 実画像

- 狭幅画面での `.map-ui`（右上の縦列 UI）折りたたみ。時刻バーは 230 px 固定のため、地図幅 < 600 px では地図の大半を覆う。
